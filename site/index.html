PP Brain

自托管的 Brain API 服务端，给 PP Friend 用。

手机端只采音放音；语音识别、对话、语音合成都由这个服务承担。agent 侧把它当一条纯文本通道——它既不知道、也不需要知道电话另一头是人类的声音。

参考实现：面向个人/家庭助手场景。状态全在内存，没有持久化、水平扩展或多租户隔离，也没有按公网暴露做加固——请只放在可信局域网或 VPN 后面。

它是什么

全双工

人类侧一边持续轮询"有没有话说"，一边把语音送上去。两条路并行，互不阻塞。

可打断

用户开口就清空播放队列，没听完的部分通过 unheard_text 补回给 agent。

流式合成

整条回复交给流式 TTS，音频边生成边转发，不等整条合成完。

状态全内存

每个 brain_id 的历史和队列都在进程里。空闲 2 小时卸载，重启即清零。

不跑模型

转写、合成、对话都打外部端点，地址由 .env 给。

协议很小

四个端点、MessagePack 编码、Bearer 鉴权。没有 SDK 要装。

架构

四条通道，两个方向。进 brain 的是提交、立即返回；出 brain 的是长轮询、可以空手而归。

人类侧（手机）
  ├─ POST /human-to-brain  ──▶  STT  ──▶  给 agent 的文本
  └─ POST /brain-to-human  ◀──  TTS  ◀──  agent 的文本（流式合成）

agent 侧
  ├─ POST /brain-to-agent  ◀──  转写、打断补充、校对告警
  └─ POST /agent-to-brain  ──▶  进队列，等人来取

上行：Ogg Opus 16 kHz      下行：Ogg Opus（采样率不保证，按解码器实际输出处理）

端点一览

端点方向语义编码
POST /human-to-brain人类 → brain提交语音，阻塞至转写完成，返回文本仅 MessagePack
POST /brain-to-humanbrain → 人类长轮询，前导 + Ogg 流：文本一次到齐，音频连续仅 MessagePack
POST /agent-to-brainagent → brain提交文本，立即返回，由服务端合成语音MessagePack / JSON
POST /brain-to-agentbrain → agent长轮询，取转写结果、打断补充、校对告警MessagePack / JSON
/brain-to-human 的响应是 application/octet-stream： [u32 大端 文本长度][UTF-8 文本][1 字节 flags][Ogg Opus 流]。 文本一次到齐，音频是连续流；flags 的 bit0 表示这条是 skip_before 跳过的旧消息。 细节见 Brain API 协议。

快速开始

cp .env.example .env       # 填端点、密钥、模型名，填完再起
docker compose up -d --build
docker compose logs -f brains

接口在 localhost:18781（宿主 18781 → 容器 8787）。鉴权走 Authorization: Bearer，token 留空就是不启用。

最小环境变量集（完整清单见仓库的 .env.example 与 docs）：

变量用途
STT_API_BASE_URL / STT_API_KEY转写端点（OpenAI 兼容）
TTS_API_BASE_URL / TTS_API_KEY / TTS_VOICE合成端点与默认音色（音色必填）
MIGHT_CHAT_API_KEY / MIGHT_CHAT_API_BASE_URL修订/摘要用的对话端点
MIGHT_BRAINS_TOKEN路由鉴权；空 = 不启用
